# 开发续接

## 当前状态

当前开发版本为家聚 0.0.10，原称家控，包名保持 `dev.homecontrol.app`。仓库 `tiancaiProgramer/JiaJu` 独立于 MiLink / HyperFusionWidget。首页只突出设备、更多设备和设置，账号入口不要移到首页最显眼处。

用户要求：主页逐项选择常驻设备，选几个就直接展示几个；「更多设备」必须包含全部设备；隐藏栏目折叠且可常驻，首页/全部/隐藏顺序独立保存；首页长按拖动、编辑页图标列表拖动共用首页顺序。新增 excluded 不展示集合与 hiddenModuleVisible，仅编辑页展示 excluded；隐藏栏目为空时首页和更多均省略。分类筛选是编辑页状态，平台之间以原生家庭/房间 ID 区分，不作为全局首页过滤器。刷新在后台更新，不能让按钮消失、整页重建或要求每次操作后手动刷新。

灯具希望接近米家：开关、亮度、色温、颜色、定时。电饭煲希望包含设备基础/扩展模式、自选和食谱搜索收藏；微波炉有模式与发现/食谱；门锁最终希望一次性密码、长按开锁、监控、用户管理和信息，但高级链路尚未打通。官方 App 可用于分析，成品必须独立运行，不能跳官方 App 代替控制。

## 操作和存储

账号会话只在手机，不在 NAS 包中。需要换设备测试时让用户自行登录，不能从官方 App 导出用户账号数据库。发布签名是覆盖升级所需的独立材料，仅在私有 NAS 包里。

保留现有包名、SQLite/Keystore 标识和设备摘要计算规则。`BuildIdentity` 在构建时生成证书指纹及版本，签名变化会影响已有会话兼容。`LightSchedules` 要继续识别「家控 · 」与「家聚 · 」两个旧新任务名前缀。

`build.py` 使用 Android SDK 工具直接构建，并运行全部 JVM 检查。`tests/lib/android-json.jar` 仅用于测试且固定 SHA256。`tools/Build-JiaJu.py --device-check` 另行生成同签名 instrumentation APK（云端只读，原生 UI 检查会临时改变并恢复本地展示设置）；它不属于发布 APK，验证后移除临时测试包。

`CONTINUATION.md` 说明公开构建和维护者 NAS 恢复。NAS 包自带 Git bundle 和 APK，可断网恢复；SDK/JDK 与 GitHub 登录不打包。恢复后先改本地路径并运行 `--check`，再构建。公开源码的首次提交来自更名前 0.0.4 的当前实现，原本包含其他项目调研和本机配置的历史没有上传。

## 0.0.8 观看体验

用户反馈卡顿、缺少全屏和设置冗余。通过手机米家实际摄像机页面的 AccessibilityNodeInfo 读取按钮布局，没有截取视频。家聚改为一行观看控制和右上角精简设置，未接通的声音、PTZ、录像/回看不放空按钮。

CameraActivity 保持单一 SurfaceView 不重新挂父容器，横屏沉浸时只改变布局尺寸、隐藏标题/说明，退出恢复系统栏；正常返回在全屏时仅退出全屏。CameraSettingsDialog 与 Activity 同处，打开不触发视频暂停；CameraSettings 白名单仅该型号的四项通用画面属性，仍由已有 MijiaCloud.control 做当前账号、型号、可写参数校验。不自动写配置，本轮没有测试实际设置写入。

CameraDecoder 增加独立输出 HandlerThread，以 CameraFrameClock 的 100ms 小缓冲按 PTS 安排 SurfaceView 呈现。大幅延迟/时间戳倒退重新锚定，避免积累直播延迟；设备支持时请求低延迟解码。只在首帧更新页面提示，避免每帧触发主线程界面更新。NativeCameraSession 关闭先通知输入 EOF，再给原生进程 250ms 退出，超时销毁。

传输仍使用在该型号验证通过的逐包 ACK；一项批量 ACK 试验未稳定，已撤回，没有纳入最终版本。增加每秒 keepalive、协议关闭通知与只含枚举的失败诊断，保持无报文/地址日志。正式版本必须保留 frame-size/UID/server validation。

测试：0.0.7 回调到达统计约 20.2fps；0.0.8 真实 SurfaceView 25秒约 20.0fps，呈现间隔 p95 64ms、最长69ms。两种计时方法不同，不能算精确改善百分比。全屏实际 1920×1080，进入、返回和设置面板均保持 session 对象，渲染持续；用户首页布局不变，退出后原生进程停止。详见 VALIDATION-0.0.8.json。高清档已做约15秒短测，接收232/解码231帧，期间无视频错误。翻转能力实际为0/180/180的角度范围，设置菜单使用正常0°和翻转180°，没有发送写入测试。声音/PTZ/录像及其他型号仍未适配。

最终包0.0.8已安装，309项JVM检查与3组Go检查通过；最终设置菜单实机检查确认翻转180°选项存在，打开后取消，没有实际写设置。最终短测约15fps、最长呈现间隔84ms；前一轮25秒约20fps、最长69ms，不能保证所有场景恒定20fps。两次全屏、返回、设置均保留同一session，退出断开，原布局不变。当前短测结论为观看节奏正常，长期弱网体感仍需用户继续验证。


## 0.0.9 起播等待

用户明确「慢」指打开后很久才出现画面。旧0.0.8实测NativeCameraSession启动至首帧9292ms：授权470ms、局域网失败约5004ms、随后外网授权/首帧等约3.8秒。帧率不是起播延迟，之前15–20fps不能证明打开快或画面实时。

增加 CameraNetwork，以当前IPv4接口前缀选择优先本地/云端；不知道接口情况则保守保持本地优先。native config 的 tryLocal 缺省保持旧行为，无媒体服务器时仍先本地；外网走云端失败后仍能回退本地，支持被不同网段路由访问的摄像头。仍只使用当前账号票据中的服务器列表，无硬编码第三方服务器。

cameraTicket 复用当前加密会话里的 scoped deviceMap，仍通过 record() 校验账号/地区派生ID并每次申请新视频授权；缺记录/缓存或显示离线才 publish()。不改变控制写入和其他设备同步路径，也不扩大锁/烹饪范围。全局Vault同步锁保持，未做风险更大的并发会话改造。

云端中继候选已返回时直接探测窗口由1500ms缩短为250ms，然后开始媒体协商，并继续现有握手内的直连探测；没有中继候选时保留1500ms。两阶段确认仍保留，未删除授权、消息验证和回退。初次仅去掉局域网等待时实测4296ms，进一步减少串行探测后真实CameraActivity首帧2423ms，连续播放10秒后退出断开，布局不变。数据和SHA见VALIDATION-0.0.9.json；真实页面计时从启动视频Activity到首帧观测，每25ms观测一次回调计数，回调可能批量送达；Native测量与UI测量方法不同，不给精确改善百分比。

318项JVM和4组Go检查通过；没有录制、导出视频或写摄像头设置。手机已安装0.0.9；完成验证后移除临时检查包。后续若再反馈慢，先测首帧各阶段，不能把起播慢和帧率/持续延迟混为一谈。没有测量米家的内部选路，不能声称米家必为直连而家聚必为中继。

## 0.0.12 · 设备面板与监控功能（2026-11-08）

用户本轮指定先完成监控底部操作、插座紧凑用电行/更多及循环任务统一编辑、空调常用控制/更多。原有工作区修改保留，未提交或推送。

PanelLayout 只负责展示分类与有来源的单位转换，控制仍通过当前账号/地区/型号下的实时 schema 验证。两个插座、两个空调伴侣的去值功能定义保存在 tests/fixtures/panel-models.json。cuco.plug.v3 循环任务采用六段分号格式，保留原重复日期与末尾模式值；未知非空格式保持原值。AppSheet 替代原生白底属性编辑框；组合设置先校验全部参数，再逐项发出，首次失败即停止，不自动重发。主面板的轮询只更新值，不重新构建控件。

CameraActivity 竖屏观看栏为视频下方独立行，全屏才挂到视频层；SurfaceView 不换父容器。CameraCaptures 的 MediaStore 写入只由显式截图/录屏触发，CameraRecording 从输入参数集构造 AVC/HEVC 封装格式，不误用解码器的 video/raw 输出格式；当前只保存视频。失败/无关键帧的临时文件删除，离开页面结束录像。合成媒体检查用纯色画面，测试文件删除，没有保存真实监控画面。

对讲使用私有串行命令管道，先检查摄像机应答，取得实际音频格式后再打开麦克风。支持 Opus、PCM、G.711 A/μ-law；PCM 不存盘。停止/切后台/锁屏导致页面暂停或连接失败会停止麦克风；启动/停止的计时器按代次失效。用户明确允许在“1号监控”测试一次移动与测试音，已确认听到短音，移动未注意，不能记为实体云台验收。测试音由合成 PCM 编码发送，不代表真实麦克风权限与通话路径验收。

CameraStorage/CameraStorageDialog 只读映射存储状态和容量，录制模式按型号原始枚举编辑。CameraNas 只放行精确三型号的 nas_get_config / nas_scan / nas_list_dir / nas_set_config，访问共享的 type/addr 来自摄像机发现结果，验证所有字段；MijiaCloud.feature 负责当前账号地区、在线状态与写入时解锁。NAS 连接密码不保存到偏好或日志，留空保留原密码；已有参数和不支持状态不被合成为关闭。三型号 NAS 配置读取均返回可解析结果，实际 NAS 写入/备份未测。

回看通过只读 RDT 命令 6 取得目录，分段解密/有界重组后按所选时间找到准确片段开始与 offset。目录数据需要十几秒传输，不能把回看卡在起播笼统归因于直播慢；没有匹配片段明确提示。预热媒体使用可取消的 drain，避免等待下一帧才退出；确认 filefound 且 starttime 匹配后清空预热队列，才向解码器交付后续画面。原生启动及目录等待均有上限，不下载录像文件，不自动回退为直播来冒充回看。默认视频复用与播放后自动恢复仍关闭。
