# Embedded camera pipe

Self-contained arm64 Android executable; Java exchanges authorization and Annex-B frames over private process pipes. It does not open an HTTP service, receive the account session, log raw packets, or save video. Exact model scope: `chuangmi.camera.069a01`, `chuangmi.camera.039c01` and `xiaomi.camera.c302`, MISS vendor 4/CS2. Tries on-subnet LAN first; other networks start with ticket-derived directory servers and P2P/relay media, with a LAN fallback after cloud failure. Media candidates can start negotiation after 250 ms while direct probes continue; absent candidates retain the original 1.5 s window. With explicit user permission, cross-network HEVC decoding and continuous real-Activity rendering were verified on the named camera. LAN returned zero frames on a different subnet. Audio/PTZ are now implemented for the exact allowlist; physical validation is tracked separately from acknowledgements. Other models remain unverified; per-model tests and duration limits are recorded in `testing/device-20261106-other-cameras/`. Short tests are not a long-term stability guarantee.

- `internal/cs2/cloud.go`: adapted from kisharora/go2rtc commit `76b3e456c2f1dda97cce9f2797a668818e165488`, MIT; builds on glissmam's cloud handshake. https://github.com/kisharora/go2rtc/commit/76b3e456c2f1dda97cce9f2797a668818e165488
- PPPP initializer wire format reference: https://github.com/nosoop/pppp_api/blob/master/decode_string.cpp ; fixed protocol table and interoperability description: https://github.com/eugeneRover/micam#5-init-string-decode . `directory.go` is a local bounded implementation of that wire format, with no imported Java source.
- X25519/NaCl box precomputation and ChaCha20 use golang.org/x/crypto. Dependency source and licenses are vendored; license notices are also packaged in APK resources/META-INF.

Local changes: ticket-derived server list, eight-byte UID prefix, removal of all packet/session logging, bounded header/frame validation, UDP source checks, matching command acknowledgements, one-second keepalive, protocol-close notification and lifecycle cleanup. Media ACKs remain per-packet for the validated exact model. There is no camera wake or generic camera-configuration write in this bridge. PTZ and talk-back require explicit foreground user controls.

The binary emits a 13-byte frame header: type (1 byte), payload size (4-byte big-endian), timestamp in milliseconds (8-byte big-endian). Type 1 is a bounded JSON event; types 4/5 are H.264/H.265 Annex-B access units; types 10–13 carry the whitelisted PCM, μ-law, A-law and Opus audio payloads after an audio-format event. The first event contains an ephemeral public key. Java writes one newline-terminated JSON configuration; EOF stops media. Private keys stay inside the process.

Build runs local Go interoperability/bounds tests and cross-compiles with 16 KB ELF page alignment. No network dependency download is needed because the verified modules are vendored. Set JIAJU_GO_HOME and JIAJU_ANDROID_NDK via the portable local build configuration.


0.0.10: drain CH0 replies throughout the session to prevent an unread 10-item reply queue from terminating healthy media. Complete relay session-link requests are answered and renewed without logging their contents. A three-minute native decode test consumed 17 replies and rendered 3596 frames. Process-control input now supports bounded private JSON pause/resume/stats commands for the retained reuse experiment; default release UI does not enable reuse/recovery. No recording, audio or camera configuration commands were added.

0.0.11: Java and native model allowlists include the two additional account-verified CS2 models. Directory-request resends use the explicit ticket directory addresses rather than the mutable active probe peer. Fixed diagnostic enums distinguish directory timeout, missing handoff and relay-not-ready without logging ticket values, endpoints or packets. Existing session, bounds, authorization and frame checks remain in force.

Media negotiation is bounded to two distinct handoff endpoints from this camera's ticket-derived discovery; a failed endpoint is not selected again under a different token. Each candidate starts with fresh local deadlines while the existing overall 40-second startup timeout remains active. `handoffAttempts` is a numeric metric only. This startup fallback does not enable the disabled post-playback UI auto-recovery or idle connection reuse experiments.


0.0.12: the input pipe adds only fixed listen / PTZ direction 1–4 / speaker start-stop / bounded audio packet operations. Speaker readiness accepts a zero little-endian int32 or known JSON success; unknown replies fail closed. Outgoing codec must match the camera's observed audio codec. The Android caller opens the microphone only after readiness and stops it on release, pause, error or page exit. A synthetic short tone on the user-authorized camera was heard by the user; microphone conversation and physical PTZ movement remain separate acceptance items.

Playback reads a bounded 2 MiB RDT command-6 catalogue using the exact models' empty-payload TLV request, then selects the precise stored clip start plus an offset. The catalogue has a 30-second wait inside the existing startup deadline. Warmup consumption is cancellable even if no next frame arrives; queued warmup video is discarded, and a matching filefound/starttime acknowledgement gates export to Java. No SD media file is downloaded or saved by the native process. Android-side explicit capture/remux uses MediaStore and is independently checked with synthetic PNG, AVC and HEVC input.
